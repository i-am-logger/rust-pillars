# FFI: the quarantine crate's foreign boundary

Load this when Rust calls C (or C calls Rust), when you add a `-sys` crate or
bindgen, when a foreign handle, pointer or string crosses into Rust, or when
an `extern "C"` function is exported.

Evidence labels: **measured here** (this skill's own checks: rustc 1.94.1,
aarch64-apple-darwin; the blocks below run under `cargo xtask snippets`),
**by-reading** (the cited document says it), **inferred** (predicted, never
measured). The policy and the quarantine's lint set are in
[no-unsafe.md](no-unsafe.md); this file is what goes inside it when the
reason is a foreign library.

## Where FFI lives

- Every `extern` block, every exported symbol and every raw foreign pointer
  is in a crate whose role is `quarantine` in `layers.toml`. Nothing else may
  hold one: `unsafe_code = "forbid"` covers every other crate, in edition 2024
  both `unsafe extern` and `#[unsafe(no_mangle)]` are unsafe code, and a raw
  pointer is usable only through `unsafe`.
- **The module is the soundness boundary.** The invariant a `// SAFETY:`
  comment relies on (this pointer is non-null, this handle is open, this
  buffer is NUL-terminated) is kept by private fields, so only the module that
  declares them can break it. A safe function that some sequence of safe calls
  drives into undefined behaviour is unsound, and unsound is a bug, never a
  trade-off. The Rustonomicon's "Working with Unsafe" makes this argument:
  `unsafe` code's correctness depends on safe code in the same privacy scope.
- The public surface is safe functions on domain types. A raw `c_int`, `*mut T`
  or `*const c_char` never leaves the quarantine: it becomes a domain value, an
  `Option` or a `Result` at the boundary (the domain-type pillar applied to C).
- no-unsafe.md says: see a symbol in a disassembly with `#[inline(never)]`, not
  `#[unsafe(no_mangle)]`. That still holds everywhere else. An *export* that C
  calls by name legitimately needs `#[unsafe(no_mangle)]`, and it lives in the
  quarantine under a counted `#[expect(unsafe_code, reason)]`.

## Two crates: `-sys` and a safe wrapper

- `<name>-sys` holds the declarations, generated by bindgen, and nothing else.
  `<name>-ffi` (or a name for what it wraps) holds the RAII types and safe
  functions. Both have the quarantine role, so `cargo xtask layers` lets
  adapters and the bin call the wrapper and lets the wrapper depend on `-sys`.
  This follows the Cargo Book ("Build Scripts", the `*-sys` packages section):
  one `-sys` crate per native library, with a `links` key, so two versions of
  the library cannot link into one graph.
- Generate only what you call: bindgen's `allowlist_function` and
  `allowlist_type` keep the generated surface (and the audit) to the functions
  the wrapper uses (by-reading: bindgen's user guide).
- bindgen is a build-dependency, and `cargo xtask layers` checks build edges
  too. The quarantine role has `external = ["*"]`, so it is allowed there and
  nowhere in the domain or core.

```toml
# crates/<name>-sys/Cargo.toml (role: quarantine in layers.toml)
[package]
name = "my-project-sys"
links = "foo"            # one crate per native library (Cargo Book, `links`)
build = "build.rs"

[build-dependencies]
bindgen = "0.72"
```

```rust,ignore
// crates/<name>-sys/build.rs -- ignore: bindgen is not a dependency of this
// project, so the snippet gate cannot link it.
fn main() {
    println!("cargo::rustc-link-lib=foo");
    let out = std::path::PathBuf::from(std::env::var("OUT_DIR").unwrap());
    bindgen::Builder::default()
        .header("wrapper.h")
        .allowlist_function("foo_.*")
        .allowlist_type("foo_.*")
        .generate()
        .expect("bindgen")
        .write_to_file(out.join("bindings.rs"))
        .expect("write bindings");
}
```

- **Gap (review): `cargo xtask budgets` scans source text**, so bindings
  pulled in with `include!(concat!(env!("OUT_DIR"), "/bindings.rs"))` are not
  counted. The `-sys` crate's whole `unsafe` surface sits behind the one
  `#[expect(unsafe_code, reason)]` on the module that includes them. Count
  that expect, review the allowlist rather than the generated file, and treat
  a regenerated, larger file as an `unsafe` change.

## Data that crosses: `repr(C)`, sized integers, no Rust enums

- Every struct passed by value or pointer is `#[repr(C)]`, field for field
  with the C header, with its size `const`-asserted. The default Rust layout
  is unspecified and may reorder fields (Rustonomicon, "Alternative
  representations").
- Use `core::ffi::c_int`, `c_char`, `c_void` and fixed-width integers, never
  `usize` for a C `int`.
- Never accept a Rust `enum`, `bool` or `char` from C. Any bit pattern outside
  the declared values is undefined behaviour the moment it exists, and C can
  send one. Take the C integer and convert it with `TryFrom` into a domain
  enum. An unknown value is then an error, not UB.
- A nullable pointer is `Option<NonNull<T>>` or `Option<extern "C" fn(..)>`.
  The null-pointer optimisation gives these the C pointer's size, so null
  becomes `None` with no extra field (Rustonomicon, "FFI", the nullable
  pointer optimisation).

```rust
use core::ffi::c_int;

/// The C struct, field for field (`struct foo_status { int code; uint32_t len; }`).
#[repr(C)]
#[derive(Debug, Clone, Copy)]
pub struct RawStatus {
    code: c_int,
    len: u32,
}
const _: () = assert!(size_of::<RawStatus>() == 8);

/// The domain view. C never constructs this directly.
#[derive(Debug, PartialEq, Eq)]
pub enum Status {
    Ready,
    Busy,
}

/// An integer the library sent that names no `Status`.
#[derive(Debug, PartialEq, Eq, Clone, Copy)]
pub struct UnknownStatus;

impl TryFrom<RawStatus> for Status {
    type Error = UnknownStatus;
    fn try_from(raw: RawStatus) -> Result<Self, UnknownStatus> {
        match raw.code {
            0 => Ok(Status::Ready),
            1 => Ok(Status::Busy),
            _ => Err(UnknownStatus),
        }
    }
}

assert_eq!(Status::try_from(RawStatus { code: 1, len: 0 }), Ok(Status::Busy));
assert_eq!(Status::try_from(RawStatus { code: 7, len: 0 }), Err(UnknownStatus));
```

## Strings: `CStr`/`CString` for C, `OsStr` for the OS

- A C string is NUL-terminated bytes with no length, not UTF-8. Borrow one as
  `&CStr` (with `c"..."` literals for constants) and own one as `CString`.
  `CString::new` refuses an interior NUL with `NulError`, so pass that error up
  instead of truncating.
- Convert to `&str` only with `CStr::to_str`, which returns a `Result`; a C
  library owes you no UTF-8.
- Paths, environment variables and arguments are `OsStr`/`OsString` and `Path`,
  because the platform's string is not UTF-8 on every OS. On Unix,
  `std::os::unix::ffi::OsStrExt::as_bytes` gives the bytes to build a `CString`.
- In a `no_std` quarantine, `CStr` is `core::ffi::CStr` and `CString` is
  `alloc::ffi::CString`.

## Ownership: allocate and free on the same side, behind RAII

- Memory is freed by the allocator that made it. A pointer from C's `malloc`
  goes back to C's `free` (or the library's own `foo_free`). A `Box` or `Vec`
  given to C comes back to Rust to be dropped. Mixing them is undefined
  behaviour, because Rust's global allocator need not be C's.
- Every foreign handle has one owner: a wrapper whose `Drop` releases it, so
  every exit path, including `?` and a panic, releases it once. This is rung 3
  of own, don't leak ([zero-copy.md](zero-copy.md#own-dont-leak)).
- Null becomes `None` (or an `Err`) in the constructor, so a wrapper that exists
  always holds a live handle and no method re-checks it.
- **A raw pointer makes the wrapper `!Send` and `!Sync`, and that is the right
  default.** Write `unsafe impl Send` or `Sync` only with a doc comment saying
  which documented guarantee of the C library makes it hold, citing the
  Rustonomicon's "Send and Sync". Never write one to silence a compile error;
  clippy `non_send_fields_in_send_ty` flags the commonest wrong one.

Measured here: libc's `strdup` and `free` behind one owner, run with
`deny(unsafe_code, unfulfilled_lint_expectations)` like a quarantine. Removing
the block's `#[expect]` failed with "usage of an `unsafe extern` block", and a
stale one failed as unfulfilled, so each expect sits where rustc flags `unsafe`.

```rust
#![deny(unsafe_code, unfulfilled_lint_expectations)]
use core::ffi::{CStr, c_char, c_int, c_void};
use core::ptr::NonNull;

#[expect(unsafe_code, reason = "declaring libc functions")]
unsafe extern "C" {
    fn strdup(s: *const c_char) -> *mut c_char;
    fn free(p: *mut c_void);
    /// `safe`: abs has no precondition, so callers need no `unsafe`. Writing
    /// `safe` is itself the promise, made once here.
    safe fn abs(x: c_int) -> c_int;
}

/// A C-allocated copy of a string. Dropping it calls C's `free`, the
/// allocator that made it. Holds a raw pointer, so it is `!Send`/`!Sync`.
#[derive(Debug)]
pub struct CDup(NonNull<c_char>);

impl CDup {
    /// `None` when `strdup` returns null (out of memory).
    pub fn new(s: &CStr) -> Option<Self> {
        #[expect(unsafe_code, reason = "calling a foreign function")]
        // SAFETY: `s` is a valid NUL-terminated string for the whole call,
        // and strdup only reads it.
        let p = unsafe { strdup(s.as_ptr()) };
        NonNull::new(p).map(Self)
    }

    /// Borrows the copy; the borrow cannot outlive `self`, so not `free`.
    #[expect(unsafe_code, reason = "reading a foreign string")]
    pub fn as_c_str(&self) -> &CStr {
        // SAFETY: the pointer is non-null (checked in `new`), NUL-terminated
        // (strdup's contract), and freed only by `Drop`, which needs `&mut self`.
        unsafe { CStr::from_ptr(self.0.as_ptr()) }
    }
}

impl Drop for CDup {
    fn drop(&mut self) {
        #[expect(unsafe_code, reason = "returning memory to its allocator")]
        // SAFETY: the pointer came from strdup, and this is its only free.
        unsafe { free(self.0.as_ptr().cast()) };
    }
}

let d = CDup::new(c"tty0").expect("strdup");
assert_eq!(d.as_c_str(), c"tty0");
assert_eq!(d.as_c_str().to_str(), Ok("tty0"));
assert_eq!(abs(-3), 3); // a `safe fn` item: no `unsafe` at the call
```

## Exports: no unwind crosses `extern "C"`

- Every `extern "C"` function C can call catches panics with
  `std::panic::catch_unwind` and returns an error code. Since Rust 1.81 a panic
  that reaches an `extern "C"` boundary aborts the process (by-reading: the
  1.81 release notes), so without the catch a bug in Rust kills the host
  program instead of failing one call.
  Measured here: a panicking `extern "C" fn` aborted (exit 134, "non-unwinding
  panic") even inside the caller's `catch_unwind`.
- Use `extern "C-unwind"` only when both sides are built to unwind through each
  other; it is not the default.
- A `no_std` quarantine has no `catch_unwind`. There, `panic = "abort"` is the
  policy. Cargo reads `[profile]` only from the workspace root `Cargo.toml`
  (Cargo Book, "Profiles"), so it applies to every artifact the workspace
  builds; make every export total (no panics reachable), so it never fires.
- Exported names need `#[unsafe(no_mangle)]` (or `#[unsafe(export_name)]`):
  two crates exporting one name is undefined behaviour at link time, which is
  why edition 2024 makes the attribute unsafe. Measured here: without its
  `#[expect]` the export below fails with "declaration of a `no_mangle` function".

```rust
#![deny(unsafe_code, unfulfilled_lint_expectations)]
use core::ffi::c_int;
use std::panic::catch_unwind;

/// The Rust work, which may panic (here, on a negative input).
fn double(n: c_int) -> c_int {
    assert!(n >= 0, "negative input");
    n.saturating_mul(2)
}

/// Exported to C. Returns the doubled value, or -1 if the Rust side panicked.
#[expect(unsafe_code, reason = "exporting an unmangled symbol")]
#[unsafe(no_mangle)]
pub extern "C" fn rc_example_double(n: c_int) -> c_int {
    catch_unwind(|| double(n)).unwrap_or(-1)
}

assert_eq!(rc_example_double(21), 42);
assert_eq!(rc_example_double(-1), -1); // panicked, caught, reported: no abort
```

- The closure captures only a `c_int`, so it is `UnwindSafe`. A closure that
  captures `&mut` state needs `AssertUnwindSafe`, and then the state must be
  checked or discarded after a caught panic, because it may be half-updated.
- An export that takes pointers is `pub unsafe extern "C" fn` with a
  `# Safety` section (clippy `missing_safety_doc`). A safe export that
  dereferences a pointer argument is unsound (clippy
  `not_unsafe_ptr_arg_deref`).

## Testing the boundary

- Miri on the quarantine runs the pure-Rust `unsafe` (pointer arithmetic,
  `CStr::from_ptr` over Rust-owned bytes, the RAII logic with a Rust stand-in
  for the C function). Miri does not execute arbitrary foreign code, so the
  real C calls need sanitizers (AddressSanitizer for use-after-free and double
  free, LeakSanitizer for a missing `Drop`) on a real host. Commands: the
  rust-qa skill (`qa:miri`, `qa:sanitize`, both planned).
- Test each wrapper with the inputs that reach each boundary: an empty string,
  an interior NUL, a null return (out of memory or not found), an unknown enum
  integer, and a panic inside an export.
- CONFORMS to BeautifulRust's FFI list (`repr(C)`, `CString`/`CStr`, same-side
  free, RAII, null to `Result`, `catch_unwind`, bindgen `-sys`).
- DEPARTS from BeautifulRust: it allows FFI in any module that keeps its
  invariant, and rust-pillars allows it only inside a declared quarantine crate
  with counted expects, because a finite audit needs one place to look.
